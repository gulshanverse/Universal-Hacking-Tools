# Verification History

This directory records controlled verification events without overwriting earlier status decisions. A history record describes the review date, scope, reviewer role or handle when intentionally provided, evidence limits, changes, and follow-up work.

Verification history is not a substitute for claim-level evidence. It should answer what was reviewed, when it was reviewed, by whom or which review role, what changed, and why a status changed. Do not store email addresses, personal data, credentials, private ticket content, or other sensitive information.

Entries use YAML and are reviewed as source records. Generated trust and verification artifacts consume current page metadata and the selective evidence ledger; they do not silently rewrite historical entries.
