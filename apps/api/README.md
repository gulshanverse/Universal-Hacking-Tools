# Phase 7–11 Knowledge API

The API is a **versioned, read-mostly public adapter** over deterministic JSON contracts generated by this repository, with separate private learning and controlled collaboration application-state boundaries. It is intentionally not a second source of truth: Markdown and YAML remain authoritative, while `generated/*.json` is the only cybersecurity knowledge-data input used at request time.

## Run locally

```bash
cd /path/to/Universal-Hacking-Tools
python3 -m pip install -r apps/api/requirements.txt
cp apps/api/.env.example apps/api/.env
make db-up && make db-migrate
PYTHONPATH=apps/api:. python3 -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

OpenAPI is published at `/openapi.json`; interactive documentation is available outside explicitly configured production mode. Regenerate the committed contract after changing routes with `python3 apps/api/scripts/export_openapi.py`, then verify it with `PYTHONPATH=apps/api:. python3 apps/api/scripts/check_openapi.py`.

## Contract boundary

The service loads `search-index.json`, `knowledge-graph.json`, `knowledge-health.json`, `graph-health.json`, `trust-report.json`, `review-queue.json`, `lab-catalog.json`, and `lab-health.json`. It reuses the existing deterministic search, discovery, recommendation, comparison, health, and graph-intelligence engines. It does not parse repository Markdown per request, mutate source content, call remote services, or collect telemetry. PostgreSQL is optional for public reads and may store only private accounts, sessions, profile preferences, learning references, progress, bookmarks, plain-text notes, safe-lab summaries, achievements, recommendation snapshots, and Phase 10 community profiles, controlled proposal/review records, private reports, deterministic reputation events, and audit events.

| Area | Public route family | Boundary |
| --- | --- | --- |
| Discovery | `/api/v1/knowledge`, `/api/v1/search`, `/api/v1/compare` | Deterministic generated data only |
| Graph exploration | `/api/v1/graph/*`, `/api/v1/knowledge/{id}/related`, `/path`, `/recommendations` | Generated graph only; depth ≤4, nodes ≤100, edges ≤200, paths ≤25; CSV/JSON export is public generated data only |
| Trust and quality | `/api/v1/trust`, `/health/*`, `/review/queue` | Transparent generated reports |
| Labs | `/api/v1/labs`, `/api/v1/lab-instances/*` | Published local-fixture definitions only |
| Authentication | `/api/v1/auth/*` | Argon2id passwords, opaque HttpOnly sessions, one-time token hashes, generic enumeration-resistant responses |
| Private learning | `/api/v1/me/*`, `/api/v1/me/knowledge-gaps` | Owner-scoped PostgreSQL references only; optional graph overlay can show only the caller's progress; CSRF required for unsafe methods |
| Community collaboration | `/api/v1/community/*`, `/api/v1/me/community/*`, `/api/v1/me/contributions/*`, `/api/v1/me/reports` | Controlled plain-text application records only; explicit non-canonical boundary, owner checks, RBAC, CSRF, private reports, and audit events |

All errors use `{"error":{"code","message","details"}}`; raw exceptions, filesystem paths, stack traces, and internal configuration values are not returned.

## Lab execution boundary

The API exposes no generic command, shell, file-upload, target-selection, scan, exploit, or remote-execution endpoint. A lab instance can be created only for an `executable` Phase 6 definition that already validates as a local, isolated, no-internet synthetic fixture. A random local session identifier scopes the ephemeral instance map. Evidence uses only declared structured records and is discarded by reset or destroy; an authenticated account may retain only status, score, task-status, and achievement summaries, never raw evidence.

Set `UHT_ALLOWED_ORIGINS` to a comma-separated, explicit development or deployment allowlist. Never use wildcard CORS with lab lifecycle or authenticated community routes. When the local web server runs at `http://127.0.0.1:3001`, include that exact origin. Set `UHT_LAB_STATE_DIR` to an approved ephemeral path when running a local lab service.

Set `DATABASE_URL`, `SESSION_SECRET`, `CSRF_SECRET`, `UHT_ALLOWED_ORIGINS`, `UHT_TRUSTED_HOSTS`, and `UHT_LAB_STATE_DIR` before enabling private application state. In production, the process rejects missing/non-PostgreSQL database configuration, non-HTTPS origins, empty trusted hosts, an implicit lab-state path, insecure cookies, and short or recognizable placeholder session/CSRF secrets. Use a secret manager, HTTPS, secure cookies, statement/pool limits, and a migration/backup rehearsal. If the database is unavailable, generated knowledge routes stay available while private routes return service unavailable; private writes are never queued.

`GET /api/v1/live` answers process liveness only. `/health` supplies minimal build/version plus artifact/database status, `/ready` distinguishes generated-contract availability from private-state degradation, and `/health/database` keeps the private database signal separate. Responses include request correlation IDs and restrictive security headers; structured request logs omit payloads, credentials, private notes, reports, and database URLs.

Run `make production-check` only with explicit production configuration. Run `make migration-preflight` after a reviewed backup; it only compares Alembic head with the configured database and never migrates. Run `make restore-verify` only after an operator has restored an isolated `test` or `staging` database. The generated [route-security matrix](../../generated/api-route-security-matrix.json) is checked for freshness. These are repository controls; domain, TLS, production PostgreSQL, backup/restore source, deployment provider, monitoring, and Git-provider credentials remain external prerequisites unless independently verified.

## Validation

```bash
PYTHONPATH=apps/api:. python3 -m unittest discover -s apps/api/tests -v
python3 apps/api/scripts/export_openapi.py
PYTHONPATH=apps/api:. python3 apps/api/scripts/check_openapi.py
```

The API test suite covers health/readiness, pagination and filters, deterministic search/discovery/comparison, trust and health reports, standardized errors, approved lab creation, local session ownership, structured evidence, assessment, reset/destroy, and the intentional absence of a generic `/execute` route.

It also covers Phase 8 migration upgrade/downgrade, registration and verification, Argon2id login sessions, anti-enumeration responses, CSRF failure, password reset and session revocation, IDOR, owner-only private state, deterministic recommendation limits, plain-text note constraints, account deletion cascades, and safe-lab summary persistence without raw evidence. Phase 9 coverage adds graph bounds, invalid filter rejection, deterministic paths, explanations, graph health, export, graph-aware direct-first search, optional owner-only progress overlays, and knowledge-gap access. Phase 10 coverage adds profile privacy, controlled proposal versioning, reviewer assignment, self-review and IDOR prevention, reviewer/maintainer/administrator RBAC, deterministic published-work expertise scoring, XSS rejection, private report handling, suspension, deletion treatment, audit/reputation records, and truthful failed or confirmed offline Git-provider handoffs.
