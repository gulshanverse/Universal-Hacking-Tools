# Phase 7–8 Knowledge API

The API is a **versioned, read-mostly public adapter** over deterministic JSON contracts generated by this repository, with a separate owner-scoped private learning-state boundary. It is intentionally not a second source of truth: Markdown and YAML remain authoritative, while `generated/*.json` is the only cybersecurity knowledge-data input used at request time.

## Run locally

```bash
cd /path/to/Universal-Hacking-Tools
python3 -m pip install -r apps/api/requirements.txt
cp apps/api/.env.example apps/api/.env
make db-up && make db-migrate
PYTHONPATH=apps/api:. python3 -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

OpenAPI is published at `/openapi.json`; interactive documentation is published at `/docs`. Regenerate the committed contract after changing routes with `python3 apps/api/scripts/export_openapi.py`, then verify it with `PYTHONPATH=apps/api:. python3 apps/api/scripts/check_openapi.py`.

## Contract boundary

The service loads `search-index.json`, `knowledge-graph.json`, `knowledge-health.json`, `trust-report.json`, `review-queue.json`, `lab-catalog.json`, and `lab-health.json`. It reuses the existing deterministic search, discovery, recommendation, comparison, and health engines. It does not parse repository Markdown per request, mutate source content, call remote services, or collect telemetry. PostgreSQL is optional for public reads and may store only private accounts, sessions, profile preferences, learning references, progress, bookmarks, plain-text notes, safe-lab summaries, achievements, and recommendation snapshots.

| Area | Public route family | Boundary |
| --- | --- | --- |
| Discovery | `/api/v1/knowledge`, `/api/v1/search`, `/api/v1/compare` | Deterministic generated data only |
| Graph exploration | `/api/v1/knowledge/{id}/related`, `/path`, `/recommendations` | Bounded depth and result limits |
| Trust and quality | `/api/v1/trust`, `/health/*`, `/review/queue` | Transparent generated reports |
| Labs | `/api/v1/labs`, `/api/v1/lab-instances/*` | Published local-fixture definitions only |
| Authentication | `/api/v1/auth/*` | Argon2id passwords, opaque HttpOnly sessions, one-time token hashes, generic enumeration-resistant responses |
| Private learning | `/api/v1/me/*` | Owner-scoped PostgreSQL references only; CSRF required for unsafe methods |

All errors use `{"error":{"code","message","details"}}`; raw exceptions, filesystem paths, stack traces, and internal configuration values are not returned.

## Lab execution boundary

The API exposes no generic command, shell, file-upload, target-selection, scan, exploit, or remote-execution endpoint. A lab instance can be created only for an `executable` Phase 6 definition that already validates as a local, isolated, no-internet synthetic fixture. A random local session identifier scopes the ephemeral instance map. Evidence uses only declared structured records and is discarded by reset or destroy; an authenticated account may retain only status, score, task-status, and achievement summaries, never raw evidence.

Set `UHT_ALLOWED_ORIGINS` to a comma-separated, explicit development or deployment allowlist. Never use wildcard CORS with lab lifecycle routes. Set `UHT_LAB_STATE_DIR` to an approved ephemeral path when running a local lab service.

Set `DATABASE_URL`, `SESSION_SECRET`, and `CSRF_SECRET` before enabling private application state. In production, use a PostgreSQL service, long randomly generated secrets in a secret manager, HTTPS, secure cookies, and a migration/backup rehearsal. If the database is unavailable, generated knowledge routes stay available while private routes return service unavailable; private writes are never queued.

## Validation

```bash
PYTHONPATH=apps/api:. python3 -m unittest discover -s apps/api/tests -v
python3 apps/api/scripts/export_openapi.py
PYTHONPATH=apps/api:. python3 apps/api/scripts/check_openapi.py
```

The API test suite covers health/readiness, pagination and filters, deterministic search/discovery/comparison, trust and health reports, standardized errors, approved lab creation, local session ownership, structured evidence, assessment, reset/destroy, and the intentional absence of a generic `/execute` route.

It also covers Phase 8 migration upgrade/downgrade, registration and verification, Argon2id login sessions, anti-enumeration responses, CSRF failure, password reset and session revocation, IDOR, owner-only private state, deterministic recommendation limits, plain-text note constraints, account deletion cascades, and safe-lab summary persistence without raw evidence.
