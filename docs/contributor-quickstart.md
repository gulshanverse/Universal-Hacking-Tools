# Contributor Quick Start

1. Browse `/contribute` for current generated opportunities such as review gaps, graph orphans, missing sources, and safe-lab needs.
2. Create a private-by-default contributor profile and choose a safe, unique username.
3. Create a bounded proposal or report. It is clearly marked **PROPOSED CONTENT — NOT CANONICAL KNOWLEDGE**.
4. Supply specific sources, relationship reasons, safety context, and controlled fields. Do not include exploit payloads, credentials, malware, target lists, uploads, or executable code.
5. Address deterministic validation findings and submit the proposal for review.
6. Respond to structured reviewer comments or withdraw an editable proposal if needed.
7. After maintainer approval, follow the linked Git pull request process. Repository CI and maintainer review decide publication.

You can also contribute directly through a normal Git workflow: fork, create a branch, edit repository Markdown/YAML using existing templates, run the documented validators, commit, and open a pull request. The application does not replace that process.
