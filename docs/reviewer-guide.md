# Reviewer Guide

Reviewers examine queued proposals using the validation findings, source list, duplicate candidates, generated canonical context, and Phase 9 graph impact preview. They should request changes when a good-faith proposal needs clearer evidence, safer framing, controlled fields, or a more precise relationship explanation. Reviewers may reject unsafe, abusive, duplicate, or unsupported proposals with a specific reason.

Reviewers cannot approve their own submissions, publish a proposal, create an automatic merge, expose security reports, or alter canonical knowledge. A reviewer recommendation is an input to a maintainer decision, not a repository change.
